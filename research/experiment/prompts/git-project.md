## Where things are

The project is the tree on the hub's branch main, whose first commit was the seed, and the spec and items the task tool shows, which only the task setter writes. A new item arrives with a sync, which task then shows. Work counts once it is on the hub's main: you commit on a branch of your own and ask for its integration, and any agent may merge requested branches into its own main, which its sync makes the hub's main if that is a fast-forward of it; a merge that conflicts leaves conflict markers in the files it lists, until you settle each and commit. When main has moved since you last merged it, merge origin/main into your branch, settle any conflict, and commit, so your work applies to the latest main. Others' work reaches you, and yours reaches them, only when you sync: it pushes your branches and fetches the hub's main and everyone's pushed branches, as origin/main and origin/<agent>/<branch>.
