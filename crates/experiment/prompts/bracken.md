## Where things are

The task is the claim tagged task and the claims tagged spec, one per function, which only the task setter's key signs. A change to the task arrives as a new spec claim superseding the old one, with a claim tagged change that states it. The library counts once it is at the hub as implementations their authors related to each function's current spec claim, with someone else's pass and no unretracted fail from anyone else; accepted lists them, and status shows what waits for a pass. Others' work reaches you, and yours reaches them, only when you sync.
